# Design: Keywords KW-16 through KW-30 Implementation

## Overview
Implement 15 keyword abilities that have working detection/parsing but stub `apply()` methods. Split into 4 types: Cost (Kicker, Flashback, Escape, Delve), Triggered/Replacement (Cascade, Storm, Madness, Dredge, Ninjutsu, Dash), Activated (Crew, Equip, Ninjutsu), Passive (Hexproof/Shroud, Menace/Reach).

## Architecture Decisions
1. **Pure transforms**: All `apply()` methods return new GameState via `model_copy(update={...})`, matching MON-01/CMD-01 pattern
2. **Centralize inline logic**: Move cascade trigger from stack.py line 665-670 and storm copies from stack.py lines 507-515 into their respective keyword modules
3. **Pending choice pattern**: Use GameState pending fields (e.g., `pending_cascade`, `pending_dredge_choice`) for human player choices, auto-resolve for AI
4. **Passive keywords as query helpers**: Hexproof/Shroud/Menace/Reach return boolean from `apply()` rather than modifying state

## Task Breakdown (Ordered by Dependency)

### Phase 1: Cost Keywords (KW-16 to KW-19)
**Task 1.1: Kicker (KW-16)**
- Implement `apply()` that checks if kicker cost was paid, sets `kicked=True` on spell
- Wire into mana payment flow in stack.py
- Test: kicker cost payment triggers additional effect

**Task 1.2: Flashback (KW-17)**
- Implement graveyard casting with flashback cost instead of mana cost
- Add exile trigger when flashback spell resolves/leaves stack
- Test: cast from graveyard, exiled after resolution

**Task 1.3: Escape (KW-18)**
- Similar to flashback but for legendary permanents from exile zone
- Implement exile cost payment and casting from exile

**Task 1.4: Delve (KW-19)**
- Implement card-from-graveyard exile as mana equivalent
- Wire into mana payment flow, reduce required mana pool payment

### Phase 2: Triggered/Replacement Keywords (KW-20 to KW-25)
**Task 2.1: Cascade (KW-20)**
- Move `_trigger_cascade()` from stack.py line 665-670 into `cascade.py`
- Implement human choice handler: keep or exile chosen card
- Wire API legal actions and choice resolution in game.py

**Task 2.2: Storm (KW-21)**
- Centralize copy creation logic from stack.py lines 507-515 into `storm.py`
- Use `spells_cast_this_turn` counter for copy count
- Test: storm spell creates N copies on stack

**Task 2.3: Madness (KW-22)**
- Implement discard replacement effect with exile + cast option
- Queue pending choice for human player, auto-cast for AI if beneficial

**Task 2.4: Dredge (KW-23)**
- Implement draw replacement: return card to library on bottom
- Use `pending_dredge_choice` field already in GameState
- Wire API handler for dredge keep/return choice

**Task 2.5: Ninjutsu (KW-24)**
- Implement activated ability: return unblocked attacker, put ninja onto battlefield
- Handle tap state and summoning sickness rules

**Task 2.6: Dash (KW-25)**
- Implement alternative casting cost with end-turn return to hand
- Track dashed creatures via `dashed_creatures` dict on GameState

### Phase 3: Passive Keywords (KW-26 to KW-30)
**Task 3.1: Hexproof/Shroud (KW-26/27)**
- Implement as query helpers in targeting validation
- Hexproof: blocks opponent's spells/abilities targeting you/your permanents
- Shroud: blocks all players' spells/abilities

**Task 3.2: Menace/Reach (KW-28/29)**
- Menace: restrict blocker selection to creatures with flying or reach
- Reach: allow blocking flying creatures
- Wire into combat/core.py blocker assignment logic

## Testing Strategy
- Unit tests for each keyword `apply()` method (pure transform verification)
- Integration tests in `test_keywords_integration.py` covering full stack flow
- API tests for human choice flows (cascade keep/exile, dredge keep/return)
- Regression: ensure existing 2156+ tests still pass

## Potential Risks
1. **Kicker mana payment integration**: Complex interaction with mana pool → Mitigation: follow existing mana payment pattern in stack.py
2. **Cascade choice timing**: Must fire before spell resolves but after casting → Mitigation: use pending_cascade field, resolve during priority window
3. **Storm copy resolution order**: Copies resolve LIFO (last created first) → Mitigation: prepend to stack, not append
